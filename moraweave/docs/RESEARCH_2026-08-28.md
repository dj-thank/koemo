# Research ledger — 2026-08-28

This ledger records the primary sources inspected for MoraWeave and separates **directly implemented interfaces**, **architectural translations**, and **future experiments**. A citation does not imply that upstream authors endorse MoraWeave.

## 1. Qwen3.8-Flash-Next

Primary sources:

- Repository: https://github.com/QwenLM/Qwen3.8-Flash-Next
- Technical report: https://github.com/QwenLM/Qwen3.8-Flash-Next/blob/main/tech_report.pdf

Relevant reported ideas:

- QSA for efficient long-context computation
- four-branch Gated Residual organization
- N-gram Embedding
- Muon-related optimization/training design

MoraWeave translation:

| Qwen3.8 idea | MoraWeave adaptation | Claim boundary |
|---|---|---|
| QSA | Query-Selected Acoustic Memory: select ambiguous audio spans instead of attending/redecoding every span equally | Architectural translation, not a QSA reimplementation |
| 4-branch Gated Residual | Four evidence streams: acoustic, mora/phone, lexical memory, disfluency preservation | Implemented in deterministic gate and optional PyTorch gate |
| N-gram Embedding | Rights-gated hashed character n-gram SQLite memory | Implemented; stores hashes/counts rather than source sentences |
| Long-context efficiency | Selective re-listening plus teacher-probability cache | Implemented as systems design; benchmark pending |
| Muon | Candidate optimizer experiment for auxiliary-head training | Not enabled by default; requires controlled training study |

## 2. Qwen3-ASR

Primary source:

- https://github.com/QwenLM/Qwen3-ASR

Relevant interfaces:

- multilingual ASR including Japanese
- long-form and contextual transcription capabilities described by the project
- a forced-aligner path described in the official repository

MoraWeave use:

- optional second-ear adapter for uncertain spans
- optional forced-alignment comparison lane
- never treated as proof that a word was spoken merely because a supplied transcript can be aligned

Status: adapter contract designed; real model download/inference is a separate acceptance test.

## 3. Whisper and faster-whisper

Primary sources:

- Whisper paper and code: https://github.com/openai/whisper
- faster-whisper: https://github.com/SYSTRAN/faster-whisper
- CTranslate2 Whisper API: https://opennmt.net/CTranslate2/python/ctranslate2.models.Whisper.html

MoraWeave use:

- the autoregressive text decoder remains intact
- the shared encoder receives optional mora CTC, phone CTC, boundary, F0, accent, and preservation heads
- N-best hypotheses remain a lattice until evidence fusion
- word/segment timestamps are evidence, not guaranteed calibrated boundaries

## 4. Japanese phonological and learner-speech evidence

Primary sources:

- Japanese speech-assessment work using mora-related labels, character recognition, pitch supervision, and lattice fusion: https://arxiv.org/abs/2509.20655
- SaSLaW learner-speech project: https://github.com/sarulab-speech/SaSLaW
- ReazonSpeech: https://github.com/reazon-research/ReazonSpeech

MoraWeave adaptation:

- multi-task supervision rather than replacing the text tokenizer with mora-only output
- explicit F0/accent and error-preservation heads
- separate evaluation for orthographic CER, kana-CER, MLER, boundary quality, and learner-error preservation
- speaker-disjoint and rights-gated evaluation requirements

Claim boundary: MoraWeave has not yet reproduced any paper's benchmark or improvement figure.

## 5. Public text and speech data

Primary sources:

- Mozilla Common Voice datasets and terms: https://commonvoice.mozilla.org/en/datasets and https://commonvoice.mozilla.org/en/terms
- JMdict / EDRDG: https://www.edrdg.org/jmdict/j_jmdict.html and https://www.edrdg.org/edrdg/licence.html
- Aozora Bunko: https://www.aozora.gr.jp/ and https://www.aozora.gr.jp/guide/kijyunn.html

MoraWeave policy:

- exact dataset version and input digests are recorded
- raw audio/text is not copied into this repository
- Common Voice speaker IDs are HMAC-pseudonymized locally
- JMdict-derived features retain attribution metadata
- Aozora Bunko requires a per-work rights manifest; corpus-wide permission is never inferred
- unknown or changed terms stop the data pipeline with `review` rather than silently becoming `allow`

## 6. Original MoraWeave mechanisms

The following are MoraWeave design proposals, not named claims from the sources above:

1. **Grammar Honeytrap** — detect a candidate preferred mainly because it is grammatical and penalize it when acoustic/mora support is weak.
2. **Mora Shadow** — retain a parallel mora/phone representation behind orthographic candidates.
3. **Selective Re-listening** — re-decode only high-entropy or cross-stream-disagreement spans before consulting a language model.
4. **Error Preservation Head** — explicitly supervise filler, restart, correction, and learner-error retention.
5. **Rights Gate** — distinguish training, feature derivation, raw redistribution, and speaker-ID export permissions.
6. **Teacher Probability Cache** — cache local teacher probabilities by audio/context/candidate digest.
7. **Counterfactual Candidate Test** — add a grammatically attractive but acoustically wrong decoy during evaluation and verify that the observed selector rejects it.

## 7. Reproducibility rule

Every experimental claim must include:

```text
code commit
model/checkpoint identifier and license
exact dataset version and rights snapshot
speaker-disjoint split digest
audio preprocessing configuration
metric implementation version
random seeds
hardware and runtime
observed and normalized outputs separately
```

No real-model quality improvement is claimed by model-free unit tests.
